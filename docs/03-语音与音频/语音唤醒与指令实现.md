# 语音唤醒与指令实现（现行方案）

> **状态**：现行方案（2026-08-29 三仓库集成后）。本文合并了选型笔记
> （根目录《语音唤醒实现参考.md》）、`docs/09-项目集成/集成方案.md` 3.5-3.10 节
> 与 `backend/models/{wakeword,pocketsphinx}/README.md` 的正式落点。
> 早期 vosk/FunASR 实验记录已废弃，见 [docs/02](../02-部署与容器) 内对应文档的废弃标注。

## 1. 双引擎架构

```
麦克风（16kHz/16bit/单声道 PCM）
   │  arecord 管道（板端 Linux）/ PyAudio（Windows）/ Dummy（无麦克风降级）
   ▼
WakeEngine（openWakeWord，ONNX，~200KB 自训模型）        ← 第一级：唤醒
   │  命中"小龙小龙" → TTS 播报"我在"
   ▼
SphinxCommandRecognizer（PocketSphinx + JSGF 语法约束）  ← 第二级：指令
   │  识别文本 → match_command_key()（中文/拼音别名归一）
   ▼
TextCommandDispatcher → Pipeline 注入的业务回调 → TTSBackend 播报结果
```

设计动机：唤醒用小模型 7×24 低算力常驻；指令识别用 PocketSphinx 的 JSGF
固定语法约束（零编译、apt 直装、误识别率低），不追求自由 ASR 精度。
**两个引擎均可独立降级**：缺依赖/缺模型时记录警告并停用语音，绝不阻塞
Pipeline 主链路。

## 2. 代码位置（backend/src/loongguard/voice/）

| 文件 | 职责 |
|---|---|
| `voice_service.py` | 生命周期与状态机（standby→active→超时回待机），独立 daemon 线程 |
| `wake_engine.py` | openWakeWord 封装 + AudioCapture 三实现（arecord/PyAudio/Dummy） |
| `command_handler.py` | PocketSphinx 识别器 + 指令别名表 + 业务分发器（同步，语音线程内执行） |
| `tts_backend.py` | TTS：pyttsx3（Windows）/ espeak（板端）/ Dummy，按平台自动选择 |

## 4. 环境变量（LG_VOICE_*，全部已在 .env.example 声明）

| 变量 | 默认 | 说明 |
|---|---|---|
| `LG_VOICE_ENABLED` | `true` | false=整体停用 |
| `LG_VOICE_WAKE_THRESHOLD` | `0.5` | 唤醒判定阈值（0~1，越高越保守） |
| `LG_VOICE_WAKE_COOLDOWN_SEC` | `3.0` | 唤醒冷却秒数 |
| `LG_VOICE_WAKE_TIMEOUT_SEC` | `8.0` | 唤醒后等待指令超时 |
| `LG_VOICE_COMMAND_DURATION_SEC` | `3.0` | 单次指令录音时长 |
| `LG_VOICE_TTS_BACKEND` | `auto` | auto/pyttsx3/espeak/dummy |
| `LG_VOICE_WAKE_MODEL_PATH` | `models/wakeword/my_wakeword.onnx` | 唤醒模型 |
| `LG_VOICE_SPHINX_MODEL_DIR` | `models/pocketsphinx/zh-cn` | 声学模型目录 |
| `LG_VOICE_SPHINX_DICT_PATH` | `models/pocketsphinx/cmudict-cn.dict` | 中文词典 |
| `LG_VOICE_SPHINX_JSGF_PATH` | `models/pocketsphinx/commands.jsgf` | 指令语法 |

## 5. 模型放置与训练

- **唤醒模型（需自行训练）**：`backend/models/wakeword/my_wakeword.onnx`。
  用 `backend/scripts/train_wakeword.py` 训练（**仅 Linux/Colab**，piper 不支持
  Windows），验收指标与放置方法见 `backend/models/wakeword/README.md`。
  缺模型时唤醒引擎自动停用（日志可见），其余功能不受影响。
- **PocketSphinx 中文声学模型**：`backend/models/pocketsphinx/zh-cn/`。
  下载 `cmusphinx-zh-cn-5.2.tar.gz`（SourceForge，注意旧文档中
  `zh_broadcastnews_16k_ptm256` 的链接已 404，勿用）并按
  `backend/models/pocketsphinx/README.md` 的三步放置法解压；`cmudict-cn.dict`
  词典与 `commands.jsgf` 语法已随仓库提供（词典已追加"温湿度"等词条）。
  声学模型不入库（.gitignore 排除）。
- 板端依赖：`sudo apt install pocketsphinx python3-pocketsphinx espeak alsa-utils`；
  Windows 开发机走 `pip install pocketsphinx pyttsx3`（requirements.txt 已含）。

## 6. 已知限制与降级语义

- 唤醒模型未训练/未放置时，语音模块整体静默停用（`LG_VOICE_ENABLED=true` 也不生效于唤醒）。
- PocketSphinx 识别率有限（集成报告实测记录在案），固定句式、靠近麦克风效果最好；
  静音段可能解码出零散词（如"关闭"），但不匹配任何指令别名，无实际影响。
- TTS 播报与麦克风采集共享声卡时，唤醒提示音"我在"可能被采进指令窗口（回声），
  造成偶发误指令——板端联调时可通过音量/距离缓解，长期可在唤醒后插入采集静默期。
- `pocketsphinx.Decoder.default_config()` 在新版绑定上有弃用警告，属预期内；
  保留旧写法是为了兼容板端 apt 源的绑定版本。
