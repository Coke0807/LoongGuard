## 二、与方案的差异决策（重要）

集成过程中发现方案的两处前提与现实不符，已按"保持已确认决策不变"的原则处理：

### 2.1 小程序 API 面：实现旧版 `/mini/*` 全部端点（而非仅 website 的 3 个）

**发现**：小程序页面实际调用 8 个端点（`/login`、`/bind-phone`、`/get-student-list`、
`/update-info`、`/unbind-student`、`/get-notice-list`、`/read-notice`、`/get-growth-list`），
全部来自被方案标记"不集成"的旧版 `routers/mini_app.py`；
`website/routers/wx_api.py` 只有 3 个端点且小程序并不调用。

**处理**：合并数据层取新旧两个 `db.py` 的并集（两者共用同一 schema 与
`class_monitor.db`），在 aiohttp 中以 `/api/wx` 前缀实现小程序全部 8 个端点
（响应结构与旧版逐字段一致），同时保留 website 的 2 个兼容端点
（`GET /api/wx/student/list`、`GET /api/wx/stream/url`）。
**小程序页面代码零改动**，仅改 `config.js` 的 `apiBaseUrl`。

### 2.2 微信 appid：采用 `wxd0037d52450fefd0` 配对（用户已确认）

`project.config.json` 原 appid（`wx3933d6bd4cbdf142`）在整个代码库中无对应
AppSecret；代码库唯一完整配对是 `ParentModel/.env` 的 `wxd0037d52450fefd0`。
经确认采用后者，`project.config.json` 已同步更新。

### 2.3 其余按方案落地

- **服务合并**：家长端全部路由注册进主仓库 `AlertAPIServer`（单端口 8080），
  中间件为家长端路径（`/api/wx/`、`/api/admin/`、`/admin`、`/static/`、`/uploads/`）
  豁免 Basic Auth（这些路径有独立 JWT 鉴权），限流与审计不变。
- **环境变量**：统一 `LG_PARENT_` 前缀写入根 `.env`（真实值已迁移）
  与 `.env.example`（占位值）。所有 env 读取为惰性（适配主仓库运行时
  才加载 `.env` 的时序）。
- **数据库**：`class_monitor.db` 置于 `backend/data/`（gitignore 不入库），
  沿用原有数据（1 管理员/8 幼儿/6 家长/6 公告）；全新部署时 `init_db()`
  自动建表 + 默认公告 + 默认管理员 `admin/admin123`。
- **语音双引擎**：openWakeWord（唤醒）+ PocketSphinx（指令）+ TTS
  （pyttsx3/espeak 跨平台），独立线程运行，通过回调对接 Pipeline 真实功能。
  缺依赖/缺模型时安静降级为停用（日志警告），不阻塞主链路。

## 四、语音指令与真实功能对照

| 指令 | 回调 | 实现 |
|------|------|------|
| 切换到正常课堂/午睡/公共区域模式 | `pipeline.set_mode()` | 运行状态标记 + 日志（与桌面端模式切换语义一致） |
| 切换模式 | — | TTS 追问要切到哪个模式 |
| 关闭告警 | `pipeline.ack_all_alerts()` | 查询未确认告警并逐条确认（返回确认数） |
| 查询温湿度 | `pipeline.get_sensor_data()` | 复用 `frontend/ui/mgt_rs485.py` Modbus 读取（按路径延迟加载）；失败播报"传感器异常" |
| 开始录制 | `pipeline.start_recording()` | `_FrameRecorder` cv2.VideoWriter 写 mp4 至 `backend/data/recordings/`（单次上限 60 秒） |
| 查看日志 | `pipeline.get_recent_logs()` | 查询告警库最近 5 条并播报摘要 |
| 关闭识别 | VoiceService 内部 | 回到待机 |
| 退出程序 | `pipeline._voice_shutdown()` | 置停运行标志，走与 Ctrl+C 一致的统一 stop() 清理 |

唤醒词："小龙小龙"、"晓珑监护"（需训练模型，见 6.2）。
唤醒后播报"我在"，8 秒无指令自动待机；识别不到指令播报"我没有听清"。

### 4.1 Windows 端到端冒烟实测（2026-08-29）

**PocketSphinx 模型已下载放置**（cmusphinx-zh-cn-5.2，声学模型 + 14 万词条词典），
开发机 venv 已装 pocketsphinx 5.1.1（cp313 win wheel）/ pyttsx3 / openwakeword 0.6.0。

过程中修复一个真实 bug：pocketsphinx 5.x 的 `default_config()` 预置英文 LM
与 `-jsgf` 互斥，需显式 `set_string('-lm', None)`（`command_handler.py`）。
另按词典实际键型（中文字词→音素）重写了 `commands.jsgf` 终结符，
并向词典追加"温湿度"词条（温+湿+度音素拼接）。

**识别实测**（7 段真实中文音频 → JSGF 解码 → `match_command_key`）：

| 音频 | 期望指令 | 识别输出 | 结果 |
|------|---------|---------|------|
| TTS合成"查询温湿度"（干净人声） | get_temp | `查询 温湿度` | ✅ **精确命中** |
| TTS合成"切换到午睡模式" | set_mode_nap | `查看 日志` | ❌ 语法内误识 |
| TTS合成"关闭告警" | ack_all | （无输出） | ❌ 漏识 |
| 前端mp3 sleep_mode（UI提示音素材） | set_mode_nap | `查询 温湿度` | ⚠️ 语法内但误键 |
| 前端mp3 class_mode / patrol / start_record | — | 部分词/无 | ❌ |

语言权重（lw）扫描 2.0/4.5/6.5 结果持平，静音修剪无改善——瓶颈为
GMM 声学模型的普通话区分度，**符合方案对该引擎的预期**
（"准确率低于神经网络"）。链路机制（音频→语法约束解码→中文输出→
指令映射→业务分发→TTS）已完整打通；识别准确率待板端真人近讲实测，
不达标时按方案切换 Whisper.cpp tiny 做指令段（`SphinxCommandRecognizer`
为可替换实现）。

## 七、已知限制与后续建议

1. **开发机模型桩**：`backend/models/*.onnx` 为占位文件，`run.py` 在开发机
   无法完整启动（存量问题）。API 层验证用单元测试；端到端验证需板端真实权重。
2. **串口竞争**：语音查温湿度与桌面端传感器线程各自打开同一 RS485 串口，
   理论上存在瞬时竞争（失败表现为播报"传感器异常"）。若板端高频出现，
   建议后续把传感器读取统一收敛到后端进程，前端经 API 获取。
3. **管理后台暂无改密端点**（沿用原系统现状），默认管理员口令请妥善保管。
4. **小程序监控页**为静态模拟数据（与原仓库一致）；实时视频对接为后续项
   （`/api/wx/stream/url` 已就绪，HLS 推流脚本参考分仓库 `start_stream.sh`）。
5. **唤醒词模型未训练**：需按 `scripts/train_wakeword.py` 在 Linux/Colab 完成
   一次性训练；完成前语音模块自动停用。PocketSphinx 中文模型已放置于
   开发机 `backend/models/pocketsphinx/`（不入库，全新环境按其 README 重新放置）。
6. **PocketSphinx 指令识别准确率有限**（见 4.1 实测）：语法约束下可产出
   规范指令词，但普通话声学区分度弱；板端真人近讲实测不达标时，
   指令段切换 Whisper.cpp tiny（预留可替换实现）。
