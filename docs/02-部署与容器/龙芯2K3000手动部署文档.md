## 1. 目标环境与部署架构

### 1.1 硬件平台：龙芯 2K3000

| 项目 | 规格 |
| --- | --- |
| CPU | 8 × LA364E @ 2.5GHz（LoongArch64） |
| GPU | 第二代自研 GPGPU 核 LG200（单精度 256 GFLOPS，INT8 8 TOPS） |
| 内存 | 8GB（systemd 服务按 3G 内存上限运行后端） |
| 视频编解码 | 独立硬件编解码模块，4K@60fps |
| 安全模块 | SM2/3/4 硬件算法模块（本项目 SM4 走 gmssl 软实现，未用硬件模块） |

### 1.2 软件环境

| 项目 | 版本 | 说明 |
| --- | --- | --- |
| 操作系统 | Loongnix 25 桌面版（Debian 系） | 查看版本：`cat /etc/loongnix_version` |
| Python | **3.13.5（系统自带，不要升级）** | 见 4.1 节说明 |
| glibc | ≥ 2.38（Loongnix 25 基线） | 决定使用 lpypi 源（见 3.4 节） |
| pip 源 | `https://lpypi.loongnix.cn/loongson/pypi/+simple` | 龙芯官方 PyPI 镜像 + 龙芯自建 wheel |

### 1.3 部署目录规划（标准生产布局）

```
/opt/loongguard/                 # 部署根目录（与 systemd 服务单元一致）
├── backend/                     # 后端完整项目（从 Windows 传输）
│   ├── run.py                   # 后端唯一启动入口
│   ├── requirements_loongarch.txt
│   ├── config/                  # default.json + settings.py
│   ├── src/loongguard/          # 后端源码
│   ├── models/                  # ONNX 模型（约 500MB，必须传输）
│   ├── data/                    # 运行时生成（DB/备份/上传）— 可写目录
│   ├── logs/                    # 运行时日志 + SM4 加密告警 — 可写目录
│   └── .env                     # 环境变量（含 LG_SM4_KEY，勿入库）
├── frontend/                    # 前端完整项目
│   ├── run.py                   # 前端启动入口
│   ├── ui/                      # PyQt6 界面源码
│   ├── voice/                   # 语音播报 mp3（约 28 个）
│   └── venv-ui/                 # 前端虚拟环境（--system-site-packages）
└── venv/                        # 后端虚拟环境
```

### 1.4 端口与数据流

```
摄像头(/dev/video0) → 后端(8080: REST + /stream MJPEG + /ws/alerts WebSocket)
                          ↓
                    PyQt6 前端(连接 127.0.0.1:8080)
RS485 传感器(/dev/ttyUSB0) → 前端直读温湿度
GPIO(/dev/gpiochip*)       → 后端声光告警（蜂鸣器/LED）
```

前后端**必须同端口**（默认 8080），由根目录 `.env` 的 `LG_API_PORT` 统一控制。

## 3. 步骤一：系统准备

以下命令均在**板端**执行（通过显示器键鼠或 SSH）。

### 3.1 开启 SSH（如需远程操作）

```bash
sudo apt install openssh-server
sudo systemctl start ssh
sudo systemctl enable ssh
# 查看板端 IP（Windows 传输文件用）
ip addr | grep inet
```

### 3.2 安装系统包

```bash
sudo apt update
# 编译依赖：pycryptodomex 源码编译需要（gmssl 传递依赖，见 2.1 表）
sudo apt install -y gcc g++ make python3-dev
# venv 支持（PEP 668 环境下项目依赖必须走 venv）
sudo apt install -y python3-venv python3-full
# 语音播报依赖 ffplay（缺失时前端语音静默失败，注意！）
sudo apt install -y ffmpeg
# 摄像头工具（调试用）
sudo apt install -y v4l-utils
# 前端 GUI 框架（PyQt6 必须走 apt，不能用 pip，见 2.2 表）
sudo apt install -y python3-pyqt6
# GPIO 告警后端（libgpiod v1 Python 绑定，与代码 API 匹配）
sudo apt install -y python3-libgpiod
```

### 3.3 用户组权限（摄像头 / 串口）

```bash
# 摄像头访问权限
sudo usermod -aG video $USER
# RS485 传感器串口权限（/dev/ttyUSB0）
sudo usermod -aG dialout $USER
# ⚠️ 必须重新登录（或重启）使组权限生效
groups $USER   # 验证输出包含 video 和 dialout
```

### 3.4 配置龙芯 pip 源（lpypi）

按官方文档二选一：

```bash
# 方法一（推荐）：官方自动配置脚本，自动识别 glibc 版本选择镜像
wget https://cloud.loongnix.cn/releases/loongarch64/python/set-pip.sh
chmod +x set-pip.sh
./set-pip.sh          # 当前用户生效
# ./set-pip.sh -g     # 所有用户生效（需 sudo）

# 方法二：手动写入配置
mkdir -p ~/.pip
tee ~/.pip/pip.conf > /dev/null <<'EOF'
[global]
timeout = 60
index-url = https://lpypi.loongnix.cn/loongson/pypi/+simple
[install]
trusted-host = lpypi.loongnix.cn
EOF

# 更新 pip 以正确识别 manylinux loongarch64 标签（重要！）
python3 -m pip install -U pip --user
```

> **为什么是 lpypi 而不是 pypi.loongnix.cn**：Loongnix 25 的 glibc ≥ 2.38，官方文档明确 pypi.loongnix.cn（glibc 2.28 源）的 wheel 在 glibc ≥ 2.38 环境下"能装但不能正常用"。

### 3.5 硬件连接检查

```bash
# 摄像头：应看到 /dev/video0（UVC 摄像头即插即用）
ls /dev/video*
v4l2-ctl --list-devices        # 确认设备名与能力

# RS485 温湿度传感器（USB 转 RS485）：应看到 /dev/ttyUSB0
ls /dev/ttyUSB*
dmesg | tail -20               # 查看 USB 串口驱动挂载日志

# GPIO：确认 gpiochip 设备节点
ls /dev/gpiochip*
```

## 4. 步骤二：Python 虚拟环境（为什么必须 venv）

### 4.1 Python 版本：使用系统自带的 3.13.5，不要升级

- Loongnix 25 系统默认 Python 即 **3.13.5**，**不建议也不需要安装更高版本**（3.14 需自行源码编译，且本项目全部依赖在 cp313 上都有龙芯 wheel，见第 2 节矩阵）。
- 本项目代码要求 `Python >= 3.11`（`backend/pyproject.toml`），3.13.5 满足。

### 4.2 为什么必须创建 venv

Loongnix 25 遵循 **PEP 668**：系统 Python 被标记为"外部管理"（externally-managed），直接 `sudo pip install` 会被**拒绝**。官方约定：

| 安装对象 | 正确方式 |
| --- | --- |
| 项目依赖 | `python3 -m venv` 虚拟环境内 pip 安装 |
| 系统级 Python 包 | `sudo apt install python3-xxx` |
| 命令行工具 | `pipx` |

本项目**两个虚拟环境**：

| 环境 | 创建方式 | 用途 |
| --- | --- | --- |
| `/opt/loongguard/venv` | `python3 -m venv venv` | 后端（依赖全部来自 pip） |
| `/opt/loongguard/frontend/venv-ui` | `python3 -m venv venv-ui --system-site-packages` | 前端（**共享系统 PyQt6**，其余依赖来自 pip） |

> `--system-site-packages` 是前端环境的关键：让 venv 能"看见" apt 安装的 python3-pyqt6，从而绕开 PyQt6-Qt6 / PyQt6-sip 无龙芯 wheel 的问题（见 2.2 表）。

## 5. 步骤三：项目文件传输（Windows → 板）

### 方式 A：完整打包传输（首次部署 / 演示前，推荐）

在 **Windows 开发机** PowerShell 中执行：

```powershell
cd d:\User\Desktop\LoongGuard

# 打包（排除虚拟环境/缓存/日志/数据库，保留模型与语音资源）
tar -czf loongguard-deploy.tar.gz `
  --exclude=".venv" --exclude="venv" --exclude="venv-ui" `
  --exclude="__pycache__" --exclude=".pytest_cache" --exclude=".ruff_cache" `
  --exclude="logs" --exclude="*.db" --exclude=".env" `
  backend frontend .env.example

# 传输（IP 换成板端实际地址；模型较大，首次约 500MB+，耐心等待）
scp loongguard-deploy.tar.gz <用户名>@<板端IP>:/tmp/
```

在**板端**执行：

```bash
# 创建部署目录
sudo mkdir -p /opt/loongguard
sudo chown $USER:$USER /opt/loongguard

# 解压到部署目录
cd /opt/loongguard
tar -xzf /tmp/loongguard-deploy.tar.gz

# 验证关键文件就位
ls backend/run.py backend/models/best.onnx frontend/run.py frontend/voice/
```

### 方式 B：开发循环快速同步（后续迭代）

项目自带 `backend/scripts/sync.py`（基于 paramiko 的 SSH/SFTP 增量同步，在 Windows 开发机运行）：

```powershell
# 在 backend/ 目录下，配合根目录 .env 中的 LG_SSH_* 变量
cd d:\User\Desktop\LoongGuard\backend
python scripts\sync.py --dry-run   # 预览
python scripts\sync.py             # 执行同步
```

> **注意**：`sync.py` 默认同步到 `/home/cc/project/LoongGuard/`，且同步范围**不含 frontend/**（仅 src/config/tests/scripts/models/docs）。它适合开发期后端代码热更新；**正式部署请用方式 A**，保证目录结构与 systemd 服务（`/opt/loongguard/backend`）一致。

## 6. 步骤四：后端部署

以下命令均在**板端**执行。

### 6.1 创建虚拟环境

```bash
cd /opt/loongguard
python3 -m venv venv
source venv/bin/activate

python3 -m pip install -U pip    # 确保 pip 识别 loongarch64 wheel 标签
```

### 6.2 安装依赖

```bash
cd /opt/loongguard/backend
pip install -r requirements_loongarch.txt
```

预期过程说明：

- onnxruntime / numpy / opencv-python / aiohttp 直接下载龙芯构建 wheel（各 5~20MB）；
- **pycryptodomex（gmssl 传递依赖）会从源码编译，耗时 3~10 分钟属正常**（已装 gcc + python3-dev，见 3.2 节）；
- 若 pycryptodomex 编译失败，可降级方案（SM4 功能不受影响，已验证 `gmssl.sm4` 模块不调用它）：

```bash
pip install gmssl==3.2.2 --no-deps
```

### 6.3 验证核心依赖导入

```bash
python -c "
import onnxruntime, numpy, cv2, aiohttp, gmssl
from gmssl.sm4 import CryptSM4
print('onnxruntime:', onnxruntime.__version__)
print('numpy:', numpy.__version__)
print('opencv:', cv2.__version__)
print('providers:', onnxruntime.get_available_providers())
print('OK: 全部核心依赖导入成功')
"
```

预期输出包含 `onnxruntime: 1.22.1`、`numpy: 2.2.6`、`opencv: 4.12.0`、`providers: ['CPUExecutionProvider']`（LG200 的 OpenCL 加速需龙芯定制版 onnxruntime-gpu wheel，见附录 A.3）。

### 6.4 配置环境变量（.env）

```bash
cd /opt/loongguard/backend
cp /opt/loongguard/.env.example .env
chmod 600 .env
nano .env    # 或 vi .env
```

**必须修改的关键项**：

```ini
LG_ENV=production

# SM4 密钥（必须！缺失时启动报 "SM4 key not found"）
# 生成 32 字节 hex 密钥：python3 -c "import os; print(os.urandom(32).hex())"
LG_SM4_KEY=<替换为生成的64位hex字符串>

# 摄像头：板端真实设备路径
LG_CAMERA_DEVICE=/dev/video0

# 端口（保持默认 8080，与前端一致）
LG_API_PORT=8080
```

> 传感器相关（前端直读，无需后端配置）。人脸/睡姿监测默认关闭（`LG_FACE_ENABLED=false`），如需开启改 true 并确认 `models/buffalo_l/det_10g.onnx` 存在。

### 6.5 模型文件检查

```bash
cd /opt/loongguard/backend
ls -lh models/best.onnx models/movenet_lightning_int8.onnx models/buffalo_l/det_10g.onnx
```

三个文件必须存在（缺失则从 Windows 开发机重新传输 `backend/models/` 目录）。

### 6.6 冒烟测试（不依赖摄像头）

使用项目自带的 mock 视频验证完整推理链路：

```bash
cd /opt/loongguard/backend
source /opt/loongguard/venv/bin/activate
LG_CAMERA_DEVICE=tests/mock_classroom.mp4 python run.py
```

预期日志依次出现：

```
GPIO alarm ready (backend=..., arch=LoongArch)
API: http://localhost:8080
```

另开一个终端验证 API：

```bash
curl -s http://localhost:8080/metrics | grep pipeline_fps
```

`Ctrl+C` 停止。

### 6.7 板上跑测试套件（强烈建议）

```bash
cd /opt/loongguard/backend
pip install pytest pytest-asyncio pytest-cov
```

## 8. 步骤六：服务化与开机自启

### 8.1 后端 systemd 服务

```bash
# 1. 创建运行用户（如沿用当前用户可跳过，但需同步修改 service 文件中的 User/Group）
sudo useradd --system --home /opt/loongguard loongguard 2>/dev/null || true

# 2. 若使用 loongguard 用户，需移交目录属主
# sudo chown -R loongguard:loongguard /opt/loongguard

# 3. 安装服务单元（项目已带：backend/deploy/loongguard.service）
sudo cp /opt/loongguard/backend/deploy/loongguard.service /etc/systemd/system/

# 4. 服务单元默认 EnvironmentFile 指向 /opt/loongguard/backend/.env（6.4 节已就位）
sudo systemctl daemon-reload
sudo systemctl enable --now loongguard

# 5. 查看状态与日志
systemctl status loongguard
journalctl -u loongguard -f          # 跟踪日志，Ctrl+C 退出
```

服务特性（已内置）：崩溃 5 秒后自动重启（`Restart=always`）、内存上限 3G、仅放行 `/dev/video*` 与 `/dev/gpiochip*` 设备、日志进 journald。

> ⚠️ 若你使用 `loongguard` 系统用户运行，`.env` 与 `data/`、`logs/` 目录需归该用户所有，否则写入失败。

### 8.2 前端桌面自启动

```bash
# 1. 创建自启动目录
mkdir -p ~/.config/autostart

# 2. 编写启动脚本
tee ~/loongguard_ui.sh > /dev/null <<'EOF'
#!/bin/bash
# LoongGuard 前端开机自启脚本
LOG=/tmp/loongguard_ui.log
echo "==================== $(date) 启动开始 ====================" >> $LOG

# 等待后端 systemd 服务与桌面就绪（后端含模型加载，需预留时间）
sleep 10

export QT_QPA_PLATFORM=xcb
export DISPLAY=:0.0
export XDG_SESSION_TYPE=x11
export QT_AUTO_SCREEN_SCALE_FACTOR=1

cd /opt/loongguard/frontend
/opt/loongguard/frontend/venv-ui/bin/python run.py >> $LOG 2>&1

echo "==================== $(date) 程序退出 ====================" >> $LOG
EOF
chmod +x ~/loongguard_ui.sh

# 3. 注册桌面自启动项
tee ~/.config/autostart/loongguard.desktop > /dev/null <<'EOF'
[Desktop Entry]
Type=Application
Name=幼儿园AI安全卫士
Comment=LoongGuard 前端界面
Exec=/home/$USER/loongguard_ui.sh
Terminal=false
StartupNotify=false
Hidden=false
EOF

# 4. 重启验证整机自启
sudo reboot
```

> 脚本中的 `sleep 10` 用于等待后端服务与显卡驱动就绪，若重启后前端黑屏/无画面，可增大到 15~20。

## 10. 故障排查

| # | 症状 | 根因 | 解决 |
| --- | --- | --- | --- |
| 1 | `pip install` 报 `externally-managed-environment` | 未激活 venv 直接装 | `source venv/bin/activate` 后再装（见第 4 节） |
| 2 | pip 找不到任何 loongarch64 wheel，全部 `Could not find a version` | pip 源未配置为 lpypi 或 pip 过旧不识别 manylinux_2_38_loongarch64 标签 | 重做 3.4 节；确认 `pip config list` 显示 lpypi；`pip install -U pip` |
| 3 | 日志出现 `GPIO alarm ready (mock=True...)` | gpiod 不可用或引脚无权限 | `sudo apt install python3-libgpiod`；确认运行用户可访问 `/dev/gpiochip*`；核对 `default.json` 的 `alarm.buzzer_pin/led_pin` 与实际接线 |
| 4 | `pycryptodomex` 编译失败 | 缺编译工具链 | `sudo apt install gcc g++ make python3-dev` 后重试；仍失败用 `pip install gmssl==3.2.2 --no-deps` |
| 5 | 启动报 `SM4 key not found` | `.env` 缺 `LG_SM4_KEY` | 按 6.4 节生成并填入 |
| 6 | 前端报 `could not load platform plugin "xcb"` | 缺 Qt 显示环境变量 | `export QT_QPA_PLATFORM=xcb`（见 7.4 / 8.2，已写入自启脚本） |
| 7 | 前端无语音 | 缺 ffplay | `sudo apt install ffmpeg`；`which ffplay` 验证 |
| 8 | 摄像头画面黑屏 / 后端反复重启 | 设备被占用或权限不足 | 确认只有一个后端进程在跑（`ps aux \| grep run.py`）；`groups` 含 `video`；`LG_CAMERA_DEVICE=/dev/video0` |
| 9 | 传感器离线 | 串口权限/设备未挂载 | `ls /dev/ttyUSB*`；`groups` 含 `dialout`；重新插拔后 `dmesg \| tail` |
| 10 | 端口占用启动失败退出 | 8080 被占 | `ss -ltnp \| grep 8080` 找到占用进程；或改 `LG_API_PORT`（前后端同步改） |
| 11 | `PyQt6` pip 安装失败（board） | PyQt6-Qt6 / PyQt6-sip 无龙芯 wheel | 用 apt 方案（3.2 节 + 7.1 节），勿用 pip 装 PyQt6 |
| 12 | pip 下载了 x86 版 wheel 无法安装 | 误用了官方 PyPI 源 | 检查 `~/.pip/pip.conf` 与 venv 内 `pip config list`，统一指向 lpypi |
