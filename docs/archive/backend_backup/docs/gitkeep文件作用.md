`.gitkeep` 是一个用于 Git 版本控制的约定性空文件，主要用于解决 Git 无法跟踪空目录的问题。

## 核心作用
Git 只跟踪文件，不跟踪空目录。如果你创建了一个空目录（如 `logs/`、`uploads/`），Git 会自动忽略它。在目录中放置一个 `.gitkeep` 文件（内容为空），可以让 Git 跟踪这个目录，确保目录结构被保留在仓库中。

## 使用场景
1. **保留空目录结构**：例如项目中的 `logs/`、`temp/`、`uploads/` 等目录，即使当前没有内容，也需要在仓库中保留目录结构。
2. **占位符**：在开发初期，某些目录（如 `src/modules/`）可能还没有实际文件，但需要先建立目录结构。
3. **约定优于配置**：这是社区广泛接受的约定，不是 Git 的官方功能，但被大多数开发者和工具支持。

## 使用方法
1. 在需要保留的空目录中创建一个名为 `.gitkeep` 的空文件：
   ```bash
   touch logs/.gitkeep
   ```
2. 将其添加到 Git：
   ```bash
   git add logs/.gitkeep
   git commit -m "添加 .gitkeep 以保留 logs 目录"
   ```

## 类似文件
- `.gitignore`：用于忽略不需要跟踪的文件/目录。
- `.keep`：与 `.gitkeep` 功能相同，但 `.gitkeep` 更常用。

## 注意事项
- `.gitkeep` 可以是空文件，也可以包含任意内容（但通常为空）。
- 这不是 Git 的官方功能，而是社区约定，所以没有"官方文档"。
- 一旦目录中有了其他文件，`.gitkeep` 可以删除（但保留也无妨）。

简单来说，`.gitkeep` 就是给空目录"占个座"，让 Git 能跟踪并保留这个目录结构。
